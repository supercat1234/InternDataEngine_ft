# 搬运、放置失败与缓存刷屏检查

## 最终修复结果

当前远端范围的 seed=42 布局已完成完整物理抓放，保存 342 帧。最终杯子倾角约 0.59°、中心偏差约 0.18 mm，连续 60 帧通过原稳定判据。缓存复用警告为 0；105 项回归测试通过。杯盘范围、机器人位置、关节限位和质量未修改，最后落盘仍限制在 5° 内。

核心代码错误在 `TemplateController.attach_obj`：原先把整台 Aloha 的关节位置直接交给单臂 CuRobo 附加物体 API。该 API 的 FK 直接使用位置数组，不按 `joint_names` 自动筛选左右臂，导致杯子碰撞球被放错到末端坐标系中的位置。隔离实验证实：原状态中携杯模型与 `table/Desktop` 冲突，移除携杯模型后，机械臂本体无该冲突。

修复使用控制器已有的 `arm_indices` 筛选当前手臂，再通过 `raw_js_names` 将 Aloha 的 `fl_/fr_` 名称映射到单臂模型名称，最后按规划器关节顺序排列。没有删除杯子碰撞球或关闭桌面碰撞检查。

当前放置策略还解耦了两个端点约束：搬运衔接最后 12 mm 稳定落盘段；松爪后的空夹爪单独搜索 0°/±5°/±10°/±20° 撤退姿态。首组预测目标从此前预放置 0 / 落盘 6 / 撤退 0，改善为预放置 2 / 落盘 6 / 撤退 53，完整组数从 0 增至 2。修正附加模型后，实际夹持关系下有 8 组完整配对。

最终验证日志：`output/cup_plate_diagnostics/attachment_order_fixed_v2/runtime.log`、`engine/`。成功数据：`output/cup_plate_diagnostics/attachment_order_fixed_v2/data/BananaBaseTask/split_aloha/custom/pick_cup_to_plate_desk/desk_edge/2026-10-30_10_11_53_240397/`。

## 两类失败必须区分

2026-10-30 09:39、09:43、09:44 的原始 Kit 日志：完整预测规划通过、双指夹持并抬起杯子，但实抓后夹持关系变化约 10 mm、9.9°，放置刷新返回 `INVALID_START_STATE_WORLD_COLLISION`。当时杯子倾角约 8.6°，并未达到搬运允许的 60° 上限。该状态表示当前规划碰撞模型认为起点与环境冲突；尚不能仅凭此状态断言实际机械臂撞到了哪一个桌子零件，也不能直接归因于杯子本身。

09:46 运行及本次当前范围的复核，是另一类问题：盘子已改到更远的 Y=0.05~0.15 m。首组诊断中实际盘中心为 `[-0.038815, 0.063949, 0.75]`，杯中心为 `[-0.339143, -0.026242, 0.749999]`。216 组候选中的有效端点数为：

| 端点 | 有效数 |
| --- | ---: |
| 预放置（最终放置姿态上移 40 mm） | 0 |
| 落盘 | 6 |
| 松爪后撤退（同姿态上移 40 mm） | 0 |
| 三个端点共同可达 | 0 |

随后几个随机布局的预放置和撤退端点也为 0；部分布局连落盘点也没有有效 IK。该组逐个隔离障碍物的检查没有发现单个障碍物触发起点碰撞；问题已出现在端点 IK 筛选，尚未进入完整搬运路径求解。

中途允许 60° 调整不会自动改变这些端点：当前预放置、落盘、撤退仍由同一小倾角放置姿态生成。它们处在机器人边缘可达区域时，单纯放宽搬运途中姿态或增加路径重试次数无法补齐端点解。

## 本次代码修改

1. `cup_plate_planning.py` 按碰撞世界配置对象是否变化同步 IK 世界；同一世界内的每批 IK 不再反复重载整张桌子网格。阶段切换或环境更新后仍正常同步。
2. `planning_logging.py` 仅过滤 cuRobo 的精确正常缓存复用提示 `Object already in warp cache, using existing instance for: ...`。碰撞、缓存容量不足、网格异常、收敛失败等消息仍保留。过滤在本仓库启动适配器中注册，不修改外部 cuRobo 库。
3. 补充预放置/落盘/撤退三类端点的有效数量，以及预测夹持/实际夹持阶段标记。
4. 底层 `check_start_state` 存在世界碰撞分支提前返回时未恢复自碰撞检查的行为。本仓库调用处使用 `finally` 恢复自碰撞检查，避免失败污染后续路径验证。
5. 实抓后先检查实际搬运起点；若已处于无效状态，明确打印原因并结束该次规划，避免对同一起点反复尝试多个目标。
6. 实际附加杯子时筛选当前手臂关节并完成 USD/规划模型名称与顺序映射。
7. 使用短距离稳定落盘与独立空夹爪撤退姿态，避免高处预放置/撤退也被固定为小倾角杯姿。

缓存警告本身表示已有网格被正常复用，不等于发生碰撞。刷屏与上述失败不是同一个原因；反复重建世界放大了日志量和重复工作。
